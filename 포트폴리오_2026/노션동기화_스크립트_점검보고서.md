## 1. 앞선 지적 정정

앞선 답변에서 "기본 DB ID가 포트폴리오 DB가 아니라 독서 LOG DB를 가리킨다"고 문제로 지적했습니다. 스크립트 본문을 읽어 보니 **의도된 설정**입니다. 스크립트는 `도서명`, `한줄평`, `독후감본문`, `완독일`, `평점`, `추천대상`, `웹공개` 속성을 읽도록 작성돼 있고, 이 속성들은 「📖 독서 LOG & 독후감」 DB 스키마와 정확히 일치합니다. 즉 "포트폴리오 블로그"는 **독후감 블로그**이고, DB ID는 맞습니다.

## 2. 실제로 확인된 문제

| # | 문제 | 영향 | 심각도 |

| 1 | 다른 DB를 쓰도록 만든 대체 로직과 고정 정렬이 서로 맞지 않습니다. 쿼리가 항상 `완독일` 정렬과 `웹공개` 필터를 보내므로, 이 속성이 없는 DB를 환경변수로 지정하면 Notion API가 400 오류를 반환합니다. | `제목`, `발행일` 같은 대체 속성 처리가 실제로는 동작하지 않습니다. | 중 |

## 3. 수정안

원본 저장소(이 세션의 GitHub 접근 범위 밖)에 아래 변경을 적용하십시오. 같은 내용을 `노션동기화_수정안.patch`로 저장했습니다.

1. 웹공개 속성이 없거나 결과가 0건일 때의 대체 수집을 **삭제**합니다. 공개 여부가 확인되지 않은 페이지는 발행하지 않습니다.
2. `public` 판정을 `checkbox(properties['웹공개'])` 하나로 단순화합니다.
3. `DATA_SOURCE_ID`를 쓸 때는 `Notion-Version: 2025-09-03`을 사용합니다.
4. 정렬 속성을 환경변수 `NOTION_SORT_PROPERTY`(기본값 `완독일`)로 분리합니다.

## 4. 확인 절차

1. GitHub 저장소 Settings → Secrets → Actions에서 `NOTION_API_KEY` 또는 `NOTION_TOKEN`이 있는지 확인합니다.
2. Actions 탭에서 `update-portfolio-blog-from-notion` 워크플로를 수동 실행(workflow_dispatch)합니다.
3. 로그에 `Updated portfolio Notion snapshot: N posts`가 찍히는지, N이 독서 DB의 웹공개 체크 건수와 같은지 대조합니다.
